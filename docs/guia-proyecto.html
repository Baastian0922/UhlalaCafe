Fullstack Guide

Este documento explica la estructura y el propósito de cada archivo y carpeta del repositorio UhlalaCafe. Está diseñado para que cualquier desarrollador pueda entender el proyecto de forma rápida y clara, sin necesidad de revisar el código fuente.

📂 Carpetas — Para qué sirve cada una

CarpetaDescripción
assets/images/ Guarda todas las fotografías e imágenes del sitio: el logo oficial, las fotos reales de la terraza al atardecer, la fachada con la dueña y el rincón de flores. Todo lo visual que no es código va aquí.
css/ Contiene style.css — todo lo que define cómo se ve el sitio: la paleta rose-gold/platinum, tipografías, tamaños, animaciones, glassmorphism y el diseño responsivo para móviles, tablets y escritorio.
js/ Contiene main.js — toda la lógica interactiva: el menú hamburguesa, el widget "Descubrir mi Taza", las pestañas de La Carta y el scroll-spy que resalta el ítem activo en la navegación.
.github/ Configuración especial que lee GitHub: el pipeline CI/CD que despliega el sitio automáticamente a GitHub Pages con cada push, y los formularios estructurados para reportar bugs o pedir funciones.

📄 Archivos — Para qué sirve cada uno

ArchivoDescripción
index.html El archivo principal del sitio web. Contiene toda la estructura visible: el Hero, la historia, la carta, el widget, la atmósfera, los testimonios y el footer. Es el único archivo HTML del proyecto.
README.md La presentación del proyecto en GitHub. Es lo primero que ve cualquier visitante del repositorio. Explica qué es el sitio, cómo ejecutarlo localmente, la tecnología usada y cómo contribuir.
CHANGELOG.md El diario oficial de cambios. Documenta qué se agregó, corrigió o eliminó en cada versión (v1.0, v1.1, v1.2…). Sigue el estándar internacional "Keep a Changelog" con versionado semántico.
package.json El pasaporte del proyecto en el ecosistema Node.js. Define el nombre, versión, autor y los comandos de desarrollo como npm run dev para levantar el sitio localmente en un clic.
LICENSE El documento legal (licencia MIT) que declara que el código es de autoría propia y bajo qué condiciones otros desarrolladores pueden usarlo, modificarlo o distribuirlo.
.gitignore La lista negra de Git. Le dice a Git qué archivos debe ignorar y nunca subir al repositorio: archivos temporales del sistema operativo, carpetas de dependencias (node_modules/), contraseñas de entorno (.env), etc.
.editorconfig Archivo de configuración que asegura que el código siempre se escriba con el mismo estilo de sangría y formato, sin importar si usas VS Code, Cursor, WebStorm u otro editor. Evita conflictos en el historial de Git.
deploy.yml El pipeline de CI/CD con GitHub Actions. Cada vez que se hace un push a la rama main, GitHub ejecuta este archivo automáticamente y publica el sitio actualizado en GitHub Pages sin intervención manual.
